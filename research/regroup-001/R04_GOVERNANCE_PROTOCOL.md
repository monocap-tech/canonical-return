## Governance model
Three roles: investigator proposes/executes within authority; verifier independently checks the exact result and custody at claimed tier; program governor adjudicates assignment, dependencies, acceptance, exceptions and release. Roles may be performed in separate turns by same assistant if disclosed; do not describe self-review as independent merely because a new thread is used. Human user retains final authority. Central ledger records decisions; repository bytes and actual verification receipts control over prose.
An operation permission is scoped to canonical lineage, operation ID, parent accepted/staged ref as appropriate, objective, allowed operations, prohibited actions, prerequisite IDs, expected evidence, verification method, resource/stop conditions and successor jurisdiction. Generic next authorizes only the next eligible operation under current grant; cannot waive custody, change terminal objective, activate blocked descendants or silently extend recovery. User may amend grants explicitly.
Independent exploration may be authorized on clearly labeled provisional inputs without promoting dependent claims; no consumption as accepted or release of existing custody hold. Independent sibling work may proceed only if true dependency independence and resource/isolation conditions are recorded. A single failure does not automatically invalidate independent theorem subsets or unrelated work.
## State machine
Proposed -> authorized -> staged/activated -> execution terminal -> custody verified -> acceptance review -> accepted (scope-specific) -> successor eligible. Custody and review may occur in parallel after execution; both required for dependent activation. Before activation authenticate source/input pins, dependency acceptance and storage path, preflight isolation/actual ref. Execution success, mathematical success, custody and adoption are distinct axes. Failed/inconclusive/canceled/blocked states lead to bounded repair, supersession, suspension or retirement; never directly to accepted. No missing evidence silently overwritten. A successful workflow with inconclusive inequality is a successful run, not a mathematical PASS. A successful module subset in failed workflow is accepted only on authenticated module completion and strict named audit, not partial axiom prints. Counts deduplicate by declaration/source identity, report scope and alternative proofs; no RH completion fraction.
Record each operation: id, lineage, authority and scope, parent refs, typed dependencies and accepted gate IDs, source/input artifact hashes and durable refs, run IDs and statuses, result and failure paths, exact theorem/hypotheses or numerical enclosure scope, audit tier, output manifests, environment, custody readback, acceptance decision, next operation/stop. Use separate status fields: execution (not started/queued/running/success/failure/canceled), mathematical (unassessed/candidate/conditional/established/inconclusive/refuted with precise claim), custody (C0-C4 objectwise + verification tier), adoption (not reviewed/accepted for scope/blocked/superseded/retired). Computational exact center is not directed physical enclosure. Native audit is not automatically source-form attachment.

## Bounded recovery and execution (proposed defaults, not enforced)
One active dependent execution chain per lineage, at most one explicitly labeled nonactivated conditional successor draft; independent shards allowed within a bounded declared batch and shared runner budget, not a blanket ban on concurrency. Governor sets resource budget/overrides per wave; no inferred quotas. On first failure capture first actual diagnostic and distinguish compiler, numerical, mathematical, custody, tool and governance blockers. One targeted repair per unchanged diagnostic; if it recurs or no new actionable evidence emerges, stop/escalate instead of repeated polling or identical writes. Recovery grant names target, search locations, max attempts/time/call budget and exit; defaults two distinct evidence-bearing recovery attempts before escalation, no retry without changed evidence. Exact recovery preferred when feasible; functional supersession needs explicit authorization, replacement verification and downstream acceptance; nonessential historical object may be explicitly retired only after dependency trace; necessary unrecoverable dependency remains blocked. No indefinite recovery for unestablished original hash. Record each attempt once, poll only on material state change or declared checkpoint; do not create new mathematical head for status-only polls. No background monitoring claimed.
## Adaptive governance
Governor reviews risk signals: custody drift, failing same root, stale/ref mismatch, blocked dependency accumulation, new scope, residual budget exhaustion, unintended workflows, contradictory receipts, missing owner, circular RH-strength premises. Distinguish local repair from structural redesign. Reassign/merge/suspend/retire routes when evidence demands; preserve old contract and rationale, explicitly authorize changed objective and re-evaluate downstream dependencies. Do not formalize untested mathematical assumptions as governance invariants. Stable invariants: honest status, custody, dependency acceptance, authority and traceability; method/assignment/budget are revisable. Emergency hold is fail-closed for affected descendants only; unrelated work requires demonstrated independence and authorization.
